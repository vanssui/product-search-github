## `doGet`

`doGet(e)` выбирает:

- `IndexSaaS` по умолчанию;
- `Index`, если передан `?classic=1`.

HTML получает заголовок `Поиск товаров` и `XFrameOptionsMode.ALLOWALL`. Серверного JSON API в версии 51 нет.

## Вызовы `google.script.run`

Оба клиента вызывают один и тот же набор из четырёх серверных методов:

| Метод | Назначение |
|---|---|
| `getTasks()` | получить все активные задания |
| `updateTask(payload)` | записать `Найдено` или `Не найдено` и ID сотрудника |
| `uploadTaskPhoto(payload)` | записать фото в Drive и его ID в строку |
| `getTaskPhotoData(payload)` | получить фото как MIME + base64 |

Методов `takeTask`, `releaseTask`, `completeTask`, отдельного `getTaskDetails` и серверного метода статистики в версии 51 нет. Статистика/отчёты vNext вычисляются в браузере из загруженных данных или вставленного текста.

## Статусы и жизненный цикл

Допустимые статусы, известные серверу:

- активный: `Поиск`;
- результат: `Найдено`;
- результат: `Не найдено`.

В выдачу попадает строка, если:

1. она находится среди последних максимум 5000 строк листа;
2. колонка «Статус поиска» равна `Поиск` без учёта регистра;
3. зона разрешена (`B3`, `B4`, `B5`).

При завершении `updateTask` записывает результат в колонку статуса поиска и ID сотрудника в соответствующую колонку, вызывает `SpreadsheetApp.flush()` и очищает cache.

## Идентификация строки и защита

Версия 51 передаёт с клиента `sheetName` и числовой `rowNumber`.

Проверки:

- лист должен существовать;
- строка должна быть от 2 до `getLastRow()`;
- обязательные колонки должны существовать;
- перед записью строка перечитывается;
- запись выполняется только если текущий статус всё ещё `Поиск`;
- если строка уже закрыта, возвращается `alreadyClosed`, повторная запись не выполняется;
- вся операция защищена `LockService.getDocumentLock()` с ожиданием до 20 секунд.

Ограничение: версия 51 не передаёт неизменяемый token содержимого строки. Если строки были физически вставлены/удалены между чтением и обновлением, одного `rowNumber` недостаточно для криптографической проверки идентичности. Новый backend добавляет `taskToken`.

## Одновременная работа, блокировки и TTL

- Критические записи сериализуются `DocumentLock`.
- Cache активных задач живёт 20 секунд.
- Защита от повторного завершения основана на повторном чтении статуса под lock.
- В версии 51 нет резервирования задания конкретным пользователем.
- В версии 51 нет TTL владения заданием.
- Несколько сотрудников могут одновременно открыть одну карточку; первый успешный `updateTask` закрывает её, последующие получают `alreadyClosed`.

Новый backend добавляет явные `takeTask`/`releaseTask`, владельца по `employeeId + sessionId` и TTL 10 минут. Это усиление, а не существующая production-логика.

## Фотографии и Google Drive

`uploadTaskPhoto`:

1. получает `dataUrl`, MIME и имя;
2. декодирует base64;
3. создаёт файл в папке Drive;
4. добавляет ID к существующим ID;
5. хранит максимум шесть последних ID;
6. записывает ID через перевод строки в колонку «Фото товара».

`getTaskPhotoData` читает Drive file ID и возвращает base64.

Document Property: `TASK_PHOTO_FOLDER_ID`. Если property отсутствует или ID недоступен, production-код создаёт папку `Warehouse Task Photos` и записывает новый ID.

По текущей активности Drive наиболее вероятная фактическая папка версии 51:

- Folder ID: `[не публикуется]`
- 694 файла на момент аудита;
- последнее фото создано 29 июля 2026 года.

Это вывод по последней активности. Прямого read-only API для значения Document Property в интерфейсе Apps Script нет; на Диске существуют и более старые одноимённые папки, созданные прежними запусками/версиями.

## Properties и триггеры

- Script Properties: записей в настройках проекта не обнаружено.
- Document Properties: код использует только `TASK_PHOTO_FOLDER_ID`.
- Установленные триггеры: `0`.
- `onOpen` является простым trigger и добавляет меню при открытии таблицы; он не отображается в списке установленных триггеров.

## Polling и локальное состояние

- Classic UI: автоматическое обновление каждые 120 секунд.
- vNext UI: 150 секунд при видимой вкладке и 300 секунд при скрытой.
- Фоновое обновление пропускается при занятости UI/неподходящем состоянии.
- Classic хранит ID сотрудника 12 часов под ключом `warehouse_employee_id_v3`.
- vNext хранит ID сотрудника в `localStorage` под ключом `warehouse_saas_employee_id`.

## Сортировка, маршруты и поиск

Сервер сортирует по зоне, затем числовым частям MX: этаж, ряд, место, полка, ячейка; затем по WB-стикеру. MX разбирается по последним пяти dot-separated сегментам. Клиент фильтрует карточки по ID/WB-стикеру, MX, BOX, названию и связанным полям.

## Валидация и обработка ошибок

Сильные стороны:

- allow-list конечных статусов;
- проверка обязательных колонок;
- проверка диапазона строки;
- повторное чтение статуса под lock;
- cache invalidation после записи;
- UI блокирует повторное нажатие во время сохранения;
- фото сжимаются в vNext перед отправкой;
- ошибки `google.script.run` показываются пользователю.

Ограничения версии 51:

- нет HTTP JSON API;
- нет явного владения заданием и TTL;
- MIME/размер фото не ограничены на сервере allow-list и числовым лимитом;
- `getTaskPhotoData` принимает произвольный доступный Drive file ID;
- `employeeId` проверяется только на непустое значение;
- строка защищается номером и статусом, но не token содержимого;
- отсутствует request ID и единый error envelope;
- POST/idempotency contract отсутствует.
