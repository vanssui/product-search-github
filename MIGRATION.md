# План миграции

## Текущее состояние

Новая система работает только с изолированной тестовой таблицей. Production Script ID
и deployment версии 51 не изменяются и намеренно не публикуются в репозитории.

## Перед production-подключением

1. Завершить parity-тестирование на 100 синтетических строках.
2. Подтвердить работу CORS из опубликованного GitHub Pages origin.
3. Проверить блокировки двумя независимыми сессиями.
4. Проверить загрузку и чтение фото в тестовой папке.
5. Утвердить TTL владения заданием и правила освобождения.
6. Отдельно утвердить production Spreadsheet ID и production photo-folder ID.
7. Создать отдельную production-конфигурацию нового backend.
8. Выпустить новую версию только нового Apps Script-проекта.
9. Провести ограниченный пилот, сохраняя старый URL версии 51.
10. Переводить пользователей только после письменного подтверждения владельца.

## Что изменится при переключении

- `APP_CONFIG.environment` станет `production`.
- `APP_CONFIG.spreadsheetId` и `APP_CONFIG.photoFolderId` будут заменены после подтверждения.
- Тестовая функция `setupTestEnvironment` останется недоступной через HTTP API.
- GitHub repository variable `VITE_BACKEND_URL` будет указывать на утверждённое deployment нового backend.

Ни один из этих шагов не требует обновления или архивирования deployment версии 51.
